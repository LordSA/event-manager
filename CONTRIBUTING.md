# Contributing Guidelines

Please follow these guidelines before submitting a pull request.

## 🔒 Security

- Never expose secrets such as `SUPABASE_SERVICE_ROLE_KEY`, API keys, or other sensitive credentials.
- Keep environment variables in `.env.local` and never commit them.

## 🧹 Code Quality

- Write clean, readable, and maintainable code.
- Remove debugging code, unused files, and commented-out code before opening a PR.
- Follow the existing project structure and coding style.

## 🌿 Branch Naming

Use descriptive branch names, for example:

- `feature/calendar-export`
- `feature/community-dashboard`
- `fix/rbac-guard`
- `fix/calendar-overlap`
- `docs/readme-update`

## 🚀 Pull Requests

Before creating a pull request, ensure that:

- [ ] The project builds successfully (`npm run build`)
- [ ] The code has been tested
- [ ] Documentation has been updated (if required)
- [ ] No sensitive information has been committed

## 📚 Documentation

If your changes affect functionality, APIs, database structure, or the UI, please update the relevant documentation:

- `README.md`
- `project_memory.md`
- `changelogs.md`
